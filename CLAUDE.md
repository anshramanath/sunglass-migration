# Bikershades Migration — Claude Context
_Last updated: 2026-05-31_

## What this is
Migrating product data from bikershades.com (WordPress/WooCommerce) into a new multi-brand Supabase-backed app. All scripts live in `migration/`.

## Pipeline (in order)
All scripts runnable from repo root — paths are resolved relative to `__file__`.

1. `migration/pipeline/fetch_products.py` — fetches 647 products from WooCommerce Store API
2. `migration/pipeline/fetch_variations.py` — fetches 6,064 variations (crash-safe, resumes)
3. `migration/pipeline/reshape_items.py` — normalizes data, buckets by issue type into `migration/reshaped/`
4. `migration/pipeline/recategorize_items.py` — applies drops/merges, removes single-item leaves, strips non-leaf paths; outputs `migration/recategorized/`
5. `migration/pipeline/download_images.py` — downloads all images locally (crash-safe via `url_map.json`)
6. `migration/pipeline/upload_images.py` — uploads to Supabase Storage (crash-safe via `upload_map.json`)
7. `migration/pipeline/import_items.py` — inserts categorized items into Supabase DB

## Image pipeline
Images are deduplicated by URL — `url_map.json` keys by full URL so the same image referenced across many products is only downloaded and uploaded once. Folder structure under `images/` is cosmetic; the map is the source of truth.

Image resolution chain in import: `bikershades URL → url_map → local path → upload_map → storage URL`. If either lookup fails the image is dropped (no broken URLs in DB).

## Price model
- Variable products (have variations): `minPriceCents` = min of variation `regularPriceCents`, `maxPriceCents` = max. `salePriceCents = null`. `sale = true` if any variation has `sale = true`.
- Simple products (no variations): `minPriceCents = maxPriceCents = regularPrice` (WooCommerce regular price, before any sale). `salePriceCents` = sale price. `sale = salePriceCents > 0 AND salePriceCents < minPriceCents`.
- `sale_price_cents` is nullable on the `products` table only — null for variable products. `variations.sale_price_cents` is always non-null — variations are the source of truth for per-variation pricing.
- DB columns on products: `min_price_cents`, `max_price_cents`, `sale_price_cents` (nullable). DB columns on variations: `regular_price_cents`, `sale_price_cents` (not null).
- All price logic computed in reshape, not import.

## Stock model
- `stock int` replaces `in_stock boolean` on both `products` and `variations`.
- Initialized from WooCommerce `is_in_stock`: `true → 1`, `false → 0`.
- Owner can update to real quantities later. Frontend treats `stock > 0` as in stock.

## Dropped fields
- `average_rating` and `review_count` — dropped entirely. App builds its own review system from scratch.

## Database
- Supabase/Postgres, multi-brand schema
- `service_role` key used by backend — bypasses RLS
- Frontends never hit Supabase directly — go through Next.js backend
- `admins` table gates admin access (no public signup)
- Variation image stored inline on `variations` row (`image_src`, `image_name`) — variations have at most 1 image. More than 1 is a WooCommerce misconfiguration and gets bucketed separately.
